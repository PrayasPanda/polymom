# Evaluation method

Results: [results.md](results.md) (tables) and [results.json](results.json) (everything,
including per-clip confusion matrices and per-stage timings). Both files are generated by
`scripts/run_benchmark.py`; no number in them is typed by hand.

## Data

All data is public, downloaded at runtime and never committed (`data/` is git-ignored).
`scripts/prepare_eval_data.py` records sources, licenses, counts and a SHA-256 of every file
in `data/eval/manifest.json`. Availability and licenses were verified on 2026-09-30.

| Set | What | Size used | License | Why |
| --- | --- | --- | --- | --- |
| [FLEURS](https://huggingface.co/datasets/google/fleurs) test, `en_us` / `hi_in` / `or_in` | Read sentences, one per clip | 30 clips per language, ~5 min each | CC-BY-4.0 | The one public, ungated benchmark with the same sentences in English, Hindi **and Odia**, so the languages are comparable |
| [MUCS 2021](https://www.openslr.org/104/) Hindi-English test (OpenSLR 104) | Real Hindi-English code-switched lecture speech | 48 segments from 6 speakers, ~3 min | CC-BY-SA-4.0 | Genuine intra-sentential code-mixing (Hindi matrix, English terms), not synthetic |
| [AMI Meeting Corpus](https://groups.inf.ed.ac.uk/ami/corpus/), Mix-Headset, ES2004a and IS1009a | Real 4-person meetings | First 10 min of each | CC-BY-4.0 | Standard diarization benchmark; RTTMs from [pyannote/AMI-diarization-setup](https://github.com/pyannote/AMI-diarization-setup) (`only_words`) |
| Synthetic code-mixed meetings (`scripts/make_codemixed_meeting.py`) | 8 meetings, 2–5 speakers, en + hi + hi-en + or, ~25% of turns overlapping | ~6.5 min total | Derived from FLEURS and MUCS | Known ground truth (RTTM, text, language spans) for the combination the assignment targets |

Considered and not used:

- Common Voice: downloads now require accepting terms on the Mozilla Data Collective.
- Kathbath and IndicVoices: gated on Hugging Face.
- VoxConverse: the audio archive is about 20 GB, and AMI covers multi-speaker
  diarization for this size of evaluation.

### How the synthetic meetings are built

- **Code-mixed speakers** are MUCS recordings. One lecture is one real voice, so a
  meeting speaker gets 2–4 turns of genuine Hindi-English from the same person.
- **Monolingual speakers** are FLEURS clips (English, Hindi, Odia). FLEURS publishes no
  speaker ids, so a FLEURS speaker gets exactly one clip. Otherwise two different real
  voices could share one reference label and corrupt the DER ground truth.
- Every meeting has at least one Odia speaker. Turns are interleaved so that the same
  speaker never talks twice in a row when another is available.
- Turns are separated by 0.3–1.0 s pauses. With probability 0.25, a turn starts 0.4–1.2 s
  before the previous one ends and is mixed in additively.
- Language labels: FLEURS turns carry their own language. MUCS turns are labelled `hi`,
  because Hindi is the matrix language and English words are embedded.
- The generator is seeded (`--seed 7`) and fully reproducible.

## Metrics

| Metric | Definition |
| --- | --- |
| WER / CER | Corpus-level word / character error rate (Levenshtein edits ÷ reference length) after NFC normalisation, case folding and removing punctuation, including the danda (।). CER is the more meaningful number for Hindi and Odia, where word segmentation and spelling variants inflate WER |
| Code-mixed CER | CER on MUCS segments **without a language hint**: spoken LID picks the language and the region is routed, as in production |
| LID accuracy | Share of reference speech seconds whose predicted language region has the right language (clip level on FLEURS, region level on meetings) |
| DER | pyannote.metrics `DiarizationErrorRate`: missed speech + false alarm + confusion, collar 0.25 s, **overlap scored** (not skipped) |
| Speaker-count accuracy | Meetings where the number of diarized speakers equals the reference |
| cpWER / cpCER | Speaker-attributed error rate: each reference speaker's concatenated text against one system speaker's, with the best permutation; missing or extra speakers are paired with empty text, so speaker errors count |
| Meeting CER | CER of the whole meeting transcript against the reference, in time order |
| Action items / decisions P and R | On the hand-labelled fixtures in `tests/fixtures/meetings` (English, Hindi, Odia, code-mixed); a predicted item matches a gold item one-to-one when an LLM judge (or rapidfuzz ≥ 60 for the mock) says they mean the same thing |
| Grounding rate | Share of evidence quotes that the verifier found in the cited utterances |
| RTF | Wall-clock processing seconds ÷ audio seconds on the stated hardware (lower is better; model loading is included in the first clip) |

## Running it

```bash
uv run python scripts/prepare_eval_data.py        # ~1 GB download, FLEURS streamed
uv run python scripts/make_codemixed_meeting.py   # 8 meetings under data/eval/meetings

# In the CUDA image (recommended). A GPU is needed for large-v3 in reasonable time.
make docker-build-cuda
docker network create polymom-bench
docker run -d --gpus all --name polymom-ollama --network polymom-bench ollama/ollama:0.11.10
docker exec polymom-ollama ollama pull qwen2.5:7b-instruct
export HF_TOKEN=hf_...     # accept the pyannote and IndicConformer terms first
make benchmark-docker      # or: make benchmark-docker ARGS="--only asr lid"

# On the host (after `make install-ml`), with the same settings in .env:
make benchmark
```

Without `HF_TOKEN`, the gated models (pyannote diarization, IndicConformer for Odia)
cannot load. Every metric that depends on them is written as **pending**, with the reason,
instead of a number.
